# 2.6 版本模型切换功能设计及交互规范

本文档用于规范 AI 短剧创作平台「模型切换」核心功能的前置条件、模型分类体系、切换模式、模块锁定逻辑、数据持久化规则、生成状态保护机制及异常校验规则，统一系统模型选择交互与引擎调度逻辑，适配多场景（文本生成、图像生成、视频生成）用户使用需求，规避生成中断、模型错乱、权限越界问题，保障模型切换、引擎调用、任务执行的准确性与稳定性。

---

## 一、功能前置条件

### 1.1 模型配置前置依赖

模型切换功能存在前置依赖：系统必须在应用启动时完成模型配置初始化，至少存在一个可用的模型供应商及其下属模型，方可开放模型切换入口。

- **模型配置源**：`src/config/models.ts` 定义三类模型供应商数组：`TEXT_MODELS`、`IMAGE_MODELS`、`VIDEO_MODELS`
- **模型加载校验**：系统启动时校验各模型数组非空且每个模型包含 `id`、`name`、`description`、`cost` 等必要字段；若校验失败，展示系统维护提示并关闭切换入口

### 1.2 模块标识前置依赖

模型切换组件支持两种挂载模式：

- **全局模式（无 moduleId）**：组件作为全局模型快捷切换器使用，切换后直接更新全局模型状态，影响所有未锁定模块的默认模型
- **模块模式（有 moduleId）**：组件挂载到具体业务模块（如 `short-drama-storyboard-text`、`assets-view-image`），支持该模块独立锁定模型，不影响全局模型状态

**模块标识规范**：
| 模块标识 | 所属页面 | 模型类型 | 业务场景 |
|---------|---------|---------|---------|
| `short-drama-storyboard-text` | StoryboardView | text | 分镜脚本文本生成 |
| `short-drama-storyboard-video` | StoryboardView | video | 分镜视频生成 |
| `assets-view-image` | AssetsView | image | 主体形象图片生成 |

### 2.2 切换业务模式

系统支持两种模型切换业务模式，覆盖全局统一设置、模块独立设置的使用场景：

#### （1）全局切换模式

用户在全局模型选择器中切换模型，该变更将同步至所有未锁定模型的业务模块。全局切换是默认的模型设置方式，适用于希望统一使用某款模型的用户。

**生效范围**：
- 所有未通过「锁定」功能独立设置模型的模块
- 新挂载的 ModelSelector 组件（未带 moduleId 或模块未锁定）

**操作入口**：
- 顶部导航栏全局模型快捷切换器
- 各页面未锁定状态下的模型选择器

#### （2）模块锁定切换模式

用户针对特定业务模块单独锁定并切换模型，该模块后续使用被锁定的模型，不受全局切换影响。模块锁定适用于对特定模块有独立模型偏好的用户。

**生效范围**：
- 仅对锁定操作时指定的 `moduleId` 生效
- 该模块的生成任务将使用被锁定的模型，无论全局模型如何变更

**操作入口**：
- 模型选择器弹窗内的「锁定此模块模型」开关（`el-switch`）
- 开启后，该模块的模型选择将与全局模型解耦

### 2.3 模型选择器交互方式

系统提供统一的模型选择器组件（`ModelSelector.vue`），所有模型切换操作通过该组件完成，保证交互体验一致性。

#### （1）触发器展示

**触发器位置**：组件以行内触发器形式嵌入页面工具栏

**触发器结构**：
- 左侧：模型类型图标（CPU-文本 / Picture-图片 / VideoCamera-视频），渐变背景圆形
- 右上：锁定状态角标（`Lock` 图标），当模块已锁定时显示琥珀色锁定标识
- 中部：
  - 上方：`AI Engine` 标签，大写加粗，9px
  - 下方：当前模型名称 + 下拉箭头
- 样式：渐变背景（indigo→purple→pink）的边框与阴影，悬停时发光效果增强

**触发器状态**：
| 状态 | 样式 | 说明 |
|------|------|------|
| 默认 | 半透明渐变背景 + 细边框 | 正常可点击状态 |
| 悬停 | 边框高亮 + 阴影扩散 + 图标旋转 | 鼠标悬停时的动效 |
| 生成中 | `opacity-50` + `cursor-not-allowed` + Tooltip | 任务执行期间禁用点击 |
| 已锁定 | 右上角琥珀色锁定角标 | 该模块已独立设置模型 |

#### （2）模型选择弹窗

**弹窗结构**：
- 顶部标题栏：
  - 左侧：「智能引擎切换」标题 + 模块锁定开关（`el-switch`，仅 moduleId 存在时显示）
  - 右侧：模型类型标签（生文模型/生图模型/视频生成），渐变背景胶囊
- 中间内容区：按供应商分组的模型列表，最大高度 450px，超出滚动
- 生成中提示：若当前模块有生成任务进行中，顶部展示琥珀色警告卡片「生成任务进行中，请等待完成后切换模型」

**模型卡片结构**：
- 左侧：模型类型图标，12×12 圆角矩形，默认 slate-50 背景，悬停时渐变 + 缩放 + 旋转
- 中上部：模型名称（15px 加粗）+ 特性标签（`el-tag`，如「旗舰」「推荐」「极速」）
- 中下部：模型描述（12px 中灰）+ 算力豆消耗（琥珀色徽标：`{cost} 算力豆/次`）
- 右侧：选中状态圆形勾选（仅当前生效模型展示）
- 左侧边条：当前生效模型展示 indigo-500 竖条标识

**供应商分组**：
- 每个供应商以分组标题展示：供应商 Logo（灰度，悬停恢复）+ 供应商名称 + 分隔线
- 供应商内模型以单列卡片形式展示

#### （3）选中确认流程

1. 用户点击目标模型卡片（生成中状态下点击无效，无响应）
2. 触发 `selectModel` 方法：
   - 向父组件发射 `update:modelValue` 事件，更新当前模块绑定的模型 ID
   - 向父组件发射 `change` 事件，传递完整模型对象
   - 若未锁定：同步更新全局模型 Store（`setTextModel`/`setImageModel`/`setVideoModel`）
   - 若已锁定：调用 `lockModel` 更新该模块的锁定映射
3. 展示成功提示：`ElMessage.success('模型切换成功')`，1.5 秒后自动消失
4. 弹窗自动关闭

## 三、模型状态核心管理规则

### 3.1 Store 状态结构设计

模型状态通过 Pinia Store（`useModelStore`）集中管理，实现全局状态与模块锁定状态的统一调度。

```typescript
interface ModelState {
  // 全局模型选择（默认模型）
  selectedTextModel: string;    // 当前全局文本模型ID
  selectedImageModel: string;   // 当前全局图像模型ID
  selectedVideoModel: string;   // 当前全局视频模型ID
  
  // 模块锁定模型映射
  lockedModels: Record<string, { 
    type: 'text' | 'image' | 'video'; 
    modelId: string; 
  }>;
  // 键为 moduleId，值为 { type, modelId }
  
  // 用户权限列表（预留扩展）
  userPermissions: string[];
  
  // 生成中模块追踪
  generatingModules: Record<string, boolean>;
  // 键为 moduleId，值为是否生成中
}
```

### 3.2 模型解析优先级规则

组件通过计算属性 `currentModelId` 确定当前真正生效的模型 ID，解析优先级从高到低：

```
优先级1: props.modelValue（父组件直接传入的模型ID，最高优先级）
优先级2: 模块锁定模型（props.moduleId 存在且 modelStore.isLocked(moduleId)）
         → 返回 lockedModels[moduleId].modelId
优先级3: 全局模型（根据 props.type 返回对应全局模型）
         → text: selectedTextModel
         → image: selectedImageModel
         → video: selectedVideoModel
```

### 3.3 全局-模块联动同步规则

系统通过 `watch` 监听全局模型变化，实现未锁定模块的自动同步：

**同步逻辑**：
```typescript
watch(() => {
  if (type === 'text') return selectedTextModel;
  if (type === 'image') return selectedImageModel;
  return selectedVideoModel;
}, (newVal) => {
  if (!isLocked.value && newVal !== props.modelValue) {
    emit('update:modelValue', newVal);
  }
});
```

**规则说明**：
- 仅当模块未锁定时，全局模型变更才会向下同步到该模块
- 模块已锁定时，全局变更被忽略，该模块保持独立模型
- 同步触发 `update:modelValue` 事件，更新父组件绑定的模型值

## 四、模块锁定与解锁处理规则

### 4.1 锁定模型

**触发条件**：用户在模型选择弹窗中开启「锁定此模块模型」开关

**锁定逻辑**：
1. 获取当前模块生效的模型 ID（`currentModelId`）
2. 调用 `lockModel(moduleId, type, modelId)` 写入 Store
3. Store 更新 `lockedModels` 映射：`{ [moduleId]: { type, modelId } }`
4. 持久化到 `localStorage`，键名：`lockedModels`
5. 该模块后续切换模型时，仅更新锁定映射，不影响全局模型

**锁定状态可视化**：
- 触发器右上角展示琥珀色锁定角标（`Lock` 图标，10px）
- 模型名称旁展示 `(Locked)` 文字标签（8px，琥珀色）
- 弹窗内锁定开关为开启状态

### 4.2 解锁模型

**触发条件**：用户在模型选择弹窗中关闭「锁定此模块模型」开关

**解锁逻辑**：
1. 调用 `unlockModel(moduleId)` 从 Store 中移除该模块的锁定记录
2. Store 更新 `lockedModels`（`delete` 操作）
3. 持久化到 `localStorage`
4. 立即同步全局模型到当前模块：
   - 根据当前 `type` 读取全局模型 ID
   - 发射 `update:modelValue` 事件，将模块绑定的模型值恢复为全局模型

**解锁后行为**：
- 模块解除与全局模型的隔离，开始跟随全局模型变化
- 若全局模型随后被切换，该模块自动同步新模型

### 4.3 锁定数据的持久化与恢复

**存储结构**：
```json
// localStorage key: "lockedModels"
{
  "short-drama-storyboard-text": { "type": "text", "modelId": "doubao-seed-2.1-pro" },
  "assets-view-image": { "type": "image", "modelId": "doubao-seedream-5.0-lite" }
}
```

**恢复流程**：
1. Store 初始化时从 `localStorage` 读取 `lockedModels`
2. 解析 JSON 后填充到 `lockedModels` 状态
3. 各页面挂载 `ModelSelector` 时，`isLocked` 计算属性自动判断并回显锁定状态
4. `currentModelId` 计算属性按优先级解析，优先使用锁定模型

## 五、生成状态保护机制

### 5.1 生成中禁止切换

**核心原则**：任何模块在生成任务执行期间，禁止切换该模块绑定的模型，防止生成中断、数据不一致、资源浪费。

**触发条件**：`modelStore.isGenerating(moduleId)` 返回 `true`

**禁止切换的多重防护**：

| 防护层级 | 实现方式 | 说明 |
|---------|---------|------|
| 视觉层 | 触发器 `opacity-50` + `cursor-not-allowed` | 直观提示用户不可点击 |
| 提示层 | Tooltip：「生成任务进行中，请等待完成后切换」 | 悬停时解释禁用原因 |
| 交互层 | 点击事件直接 return，不打开弹窗 | 阻止弹窗打开 |
| 弹窗层 | 弹窗内展示琥珀色警告卡片 | 提示当前生成状态 |
| 操作层 | 模型卡片 `cursor-not-allowed` + `opacity-50` + `grayscale` | 弹窗内卡片禁用样式 |
| 逻辑层 | `selectModel` 方法首行判断 `isGenerating` 直接 return | 最终防线 |

### 5.2 生成状态追踪

**状态管理**：
- `modelStore.generatingModules` 记录各模块的生成状态
- 业务代码在生成开始/结束时调用 `setGenerating(moduleId, true/false)`

**示例代码（StoryboardView）**：
```typescript
watch(isGeneratingStoryboardText, (val) => {
  modelStore.setGenerating('short-drama-storyboard-text', val);
  modelStore.setGenerating('short-drama-storyboard-video', val);
});
```

**状态影响范围**：
- 文本生成中：`short-drama-storyboard-text` 模块禁止切换文本模型
- 视频生成中：`short-drama-storyboard-video` 模块禁止切换视频模型
- 同一页面的多个模块独立追踪，互不影响（文本生成中不影响视频模型切换）

### 5.3 生成中断恢复与模型一致性

**异常中断场景**：页面刷新、浏览器崩溃、用户误关闭导致生成任务中断

**恢复逻辑**：
1. 页面重新加载时，Store 从 `localStorage` 恢复状态
2. `generatingModules` 不会持久化（刷新后重置为 `{}`），避免永久锁定
3. 业务代码在 `onMounted` 中检查历史任务状态，若检测到有中断的生成任务（如 `synthesisStatus === 'synthesizing'`），展示恢复确认弹窗
4. 恢复后的任务继续使用原模型执行，不触发模型切换

## 六、模型切换异常校验与边界处理

### 6.1 非法模型 ID 校验

**触发条件**：用户传入的 `modelValue` 不在对应类型的模型列表中，或 `lockedModels` 中存储了已被移除的模型 ID

**处理逻辑**：
- 选择器遍历供应商列表查找模型，若未找到则回退到第一个供应商的第一个模型
- 回退后同步更新全局/锁定状态，确保后续使用有效模型 ID

### 6.2 模型类型不匹配校验

**触发条件**：组件 `type` 为 `text`，但传入的 `modelValue` 属于图像模型或视频模型

**处理逻辑**：
- 选择器内部不做强制拦截（由业务层控制）
- 模型列表按 `type` 过滤展示，用户仅能看到当前类型的模型，降低误选概率
- 若父组件传入跨类型模型 ID，选择器回退到该类型默认模型并展示警告

### 6.3 空模块 ID 校验

**触发条件**：组件设置 `isLockedInternal` 时 `moduleId` 为空

**处理逻辑**：
- 计算属性的 `set` 方法中首行判断 `if (!props.moduleId) return;`
- 无 `moduleId` 时锁定开关不响应，保持全局模式

### 6.4 权限校验（预留扩展）

**触发条件**：用户尝试选择需要特殊权限的模型

**处理逻辑**：
- Store 中 `hasPermission(modelId)` 方法目前默认返回 `true`（全开放）
- 后续扩展时，无权限的模型卡片可展示 `is-disabled` 样式并禁用点击
- 点击时提示：「当前模型需要升级套餐后使用」

### 6.5 并发切换防护

**触发条件**：用户快速连续切换模型

**处理逻辑**：
- 模型选择弹窗在选中后自动关闭，减少重复操作机会
- 切换操作无网络请求（纯本地状态更新），操作耗时极短，并发冲突概率极低
- 若需扩展异步切换，可在 `selectModel` 中添加 `loading` 状态锁

## 七、模型切换与业务流程的衔接规则

### 7.1 与分镜脚本生成的衔接

分镜脚本文本生成流程中，模型切换直接影响生成内容的风格与质量：

**衔接逻辑**：
1. StoryboardView 页面挂载两个 ModelSelector：
   - 文本模型：`type="text"`，`moduleId="short-drama-storyboard-text"`
   - 视频模型：`type="video"`，`moduleId="short-drama-storyboard-video"`
2. 用户点击「AI 分镜规划」时，系统读取 `modelStore.selectedTextModel` 或模块锁定模型
3. 生成请求中携带 `model: modelStore.selectedVideoModel` 参数
4. 生成结果展示时附带模型信息：`分镜 X 生成成功 (模型: {modelId}, 分辨率: {resolution})`

### 7.2 与主体形象生成的衔接

主体形象图片生成流程中，模型切换影响角色、场景、道具的生成风格：

**衔接逻辑**：
1. AssetsView 页面挂载图像模型选择器：`type="image"`，`moduleId="assets-view-image"`
2. 用户点击「生成图片」时，系统读取 `modelStore.selectedImageModel` 或模块锁定模型
3. 生成请求携带模型参数，确保不同主体使用统一或独立的图像模型

### 7.3 与算力豆扣费的衔接

每次模型切换后的首次生成，系统根据所选模型的 `cost` 字段扣除对应算力豆：

**扣费规则**：
- 文本模型：按 `cost` 值扣除（如豆包旗舰模型每次 10 算力豆）
- 图像模型：按 `cost` 值扣除（如 ChatGPT Images 2.0 每次 20 算力豆）
- 视频模型：按 `cost` 值扣除（如可灵3.0 Omni 每次 80 算力豆）
- 扣费前校验用户余额是否充足，不足时阻断生成并提示充值

### 7.4 与模型推荐的衔接

系统通过标签体系辅助用户选择模型：

**标签类型与语义**：
| 标签 | 类型 | 含义 | 适用场景 |
|------|------|------|---------|
| 推荐 | success | 平台推荐，综合表现优秀 | 默认首选 |
| 极速 | success | 响应速度快，低延迟 | 快速迭代、灵感捕捉 |
| 强力 | warning | 能力强但成本较高 | 高质量输出需求 |
| 写实 | warning | 写实风格，细节丰富 | 写实类图像/视频 |
| 旗舰 | success | 该供应商顶级模型 | 追求最佳效果 |
| 稳定 | info | 表现稳定，波动小 | 生产环境、批量任务 |

## 九、数据持久化与恢复

### 9.1 LocalStorage 存储结构

```json
// localStorage key: "selectedTextModel"
"doubao-seed-2.1-pro"

// localStorage key: "selectedImageModel"
"doubao-seedream-5.0-lite"

// localStorage key: "selectedVideoModel"
"doubao-seedance-2.5"

// localStorage key: "lockedModels"
{
  "short-drama-storyboard-text": { "type": "text", "modelId": "DeepSeek-V4" },
  "assets-view-image": { "type": "image", "modelId": "ChatGPT-Images-2.0" }
}
```

### 9.2 初始化与恢复流程

1. Store 初始化时从 `localStorage` 读取各模型配置：
   - `selectedTextModel`：取存储值或默认 `TEXT_MODELS[0].models[0].id`
   - `selectedImageModel`：取存储值或默认 `IMAGE_MODELS[0].models[0].id`
   - `selectedVideoModel`：取存储值或默认 `VIDEO_MODELS[0].models[0].id`
   - `lockedModels`：解析 JSON 或默认空对象 `{}`
2. 各页面挂载时，ModelSelector 组件通过计算属性自动解析当前生效模型
3. 全局变更时实时写入 `localStorage`，保证跨页面状态一致
4. 锁定/解锁时实时写入 `localStorage`，保证刷新后锁定状态不丢失

## 十、模型配置扩展规范

### 10.1 新增供应商

在 `src/config/models.ts` 中按以下格式添加：

```typescript
{
  id: '供应商标识（英文小写）',
  name: '供应商显示名称',
  logo: 'Logo URL（可选）',
  models: [
    {
      id: '模型唯一标识',
      name: '模型显示名称',
      description: '模型能力描述',
      provider: '供应商标识',
      tags: ['标签1', '标签2'],
      cost: 10
    }
  ]
}
```

### 10.2 新增模型类型

若未来需增加音频、3D等模型类型：
1. 在 `models.ts` 中定义新的模型数组（如 `AUDIO_MODELS`）
2. 在 `ModelState` 中增加 `selectedAudioModel` 状态
3. 在 Store 中增加 `setAudioModel` action
4. 在 `ModelSelector` 的 `type` props 中增加 `'audio'` 类型
5. 在 `vendors` 计算属性中增加对应分支
