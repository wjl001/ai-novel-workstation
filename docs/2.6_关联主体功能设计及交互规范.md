# 2.6 版本关联主体功能设计及交互规范

本文档用于规范 AI 短剧创作平台「关联主体」核心功能的前置条件、业务模式、关联方式、数据存储逻辑、自动识别匹配规则、重复关联处理规则及异常校验规则，统一系统关联主体交互与数据处理逻辑，适配多场景用户使用需求，规避数据错乱、关联失败问题，保障主体关联、存储、更新的准确性与规范性。

---

## 一、功能前置条件

### 1.1 主体库前置依赖

关联主体功能存在前置依赖：用户必须先完成「主体库」的基础配置，系统内至少存在一条有效的主体数据（角色、场景或道具），才可执行主体关联操作。

- **未配置主体库时**：系统展示空状态引导页，提示用户先前往「主体设置」模块完成角色、场景、道具的基础创建与形象设定；不开放任何关联入口。
- **主体库校验逻辑**：系统在加载关联主体弹窗或执行自动关联前，首先校验 `episodeStore.subjects` 数组长度，若长度为 0，则阻断流程并引导用户创建主体。

### 1.2 剧集数据前置依赖

执行单集关联时，目标剧集必须已完成基础创建并存在于系统剧集列表中（`episodeStore.episodes` 数组内存在对应 `index` 的剧集对象）。

- **未创建对应剧集**：自动关联逻辑将跳过该集数，仅处理已存在的剧集；手动关联弹窗中仅展示已创建的剧集索引供选择。
- **主体设置状态校验**：在分镜脚本导入场景中，系统要求目标剧集的 `assetsStatus` 必须为 `'success'`（即已完成主体设置），否则该集将被标记为 `episodesSkippedNoAssets` 并跳过关联。

## 二、核心关联功能整体设计

### 2.1 关联业务模式

系统支持两种主体关联业务模式，覆盖全局统一关联、单集精准关联的使用场景，用户可按需选择：

#### （1）全局关联（全剧关联）

将选中的主体一次性关联到剧本的全部剧集，适用于贯穿全剧的核心角色、主场景、关键道具等。全局关联后，该主体在所有集数的 `appeared_episodes` 中均包含全部索引。

**适用场景**：
- 男主角、女主角等贯穿全剧的角色
- 主舞台、主场景等反复出现的场景
- 关键道具（如信物、武器）等全剧通用元素

**操作入口**：
- 剧集管理页面（EpisodesView）顶部工具栏「关联主体」按钮
- 主体设置页面（AssetsView）全局关联快捷操作

#### （2）单集关联（分集关联）

将选中的主体单独关联到指定单集，精准控制主体在特定集数的出现。单集关联后，该主体的 `appeared_episodes` 仅包含被指定的集数索引。

**适用场景**：
- 仅在某几集出现的配角（如反派、客串角色）
- 特定集数的特殊场景（如闪回场景、梦境场景）
- 单集专用道具（如某集的关键线索物品）

**操作入口**：
- 剧集管理页面单集卡片底部「关联主体」按钮
- 分镜编辑页面（StoryboardView）侧边栏关联操作
- 导入完成后的自动关联提示快捷操作

### 2.2 关联操作方式

适配不同用户操作习惯与场景需求，提供两种主体关联操作方式，两种操作方式统一复用相同的校验、存储、数据更新逻辑：

#### （1）手动选择关联（主动关联）

用户通过「关联主体弹窗（SubjectAssociationDialog）」手动浏览主体库，自主选择需要关联的主体，支持分类筛选与搜索查询。

**操作流程**：
1. 用户点击「关联主体」按钮，触发弹窗打开
2. 系统加载当前已选状态（根据 `appeared_episodes` 回显已关联主体）
3. 用户通过分类筛选（全部/角色/场景/道具）或搜索框缩小范围
4. 用户点击主体卡片进行选中/取消选中切换
5. 用户点击「确认关联」，系统执行关联逻辑并落库

**交互细节**：
- 弹窗标题根据上下文动态变化：
  - 单集关联时：`关联主体到第 {episodeIndex} 集`
  - 全局关联时：`关联主体到整个剧本`
- 主体卡片展示：缩略图、名称、类型标签（角色/场景/道具）
- 选中态：蓝色边框 + 环形高亮 + 勾选角标
- 空态：搜索无结果时展示「未找到相关主体」引导

#### （2）自动关联（智能关联）

系统根据算法自动将主体关联到目标剧集，减少用户手动操作。自动关联提供两种触发时机：

**触发时机一：导入后自动关联**
- 在「分镜脚本批量导入」流程中，用户可勾选「导入后自动关联主体」选项
- 导入成功完成后，系统自动调用 `autoAssociateSubjects` 方法，将最近使用的主体关联到新导入的剧集

**触发时机二：主动触发自动关联**
- 用户点击「自动关联」按钮（剧集管理页顶部或单集卡片）
- 系统执行自动关联算法，将主体关联到目标剧集

### 2.3 数据落库与保存规则

主体关联操作经系统校验通过后，立即自动落库生效，无需用户手动点击额外保存按钮；仅当用户进入主体编辑页面（SubjectEditDialog），对已创建的主体字段信息进行修改调整时，需手动点击「保存」按钮，编辑修改内容才可更新至数据存储。

**落库数据字段**：
```typescript
interface Subject {
  id: string;                          // 主体唯一标识
  name: string;                        // 主体名称
  type: 'character' | 'scene' | 'prop'; // 主体类型：角色/场景/道具
  image?: string;                      // 主体形象图
  prompt?: string;                    // 主体提示词
  appeared_episodes?: number[];       // 关联的剧集索引数组，核心关联字段
  // ... 其他主体字段
}
```

**存储策略**：
- 所有关联操作通过 `episodeStore.updateSubject(id, { appeared_episodes: [...] })` 执行
- 每次状态变更后自动调用 `saveToLocalStorage()`，将 `episodeStore` 完整状态持久化到 `localStorage`（键名：`episode_store`）
- 页面刷新后通过 `loadFromLocalStorage()` 恢复关联状态，保证数据不丢失

## 三、主体关联核心识别匹配规则

### 3.1 自动关联算法逻辑

系统 `autoAssociateSubjects` 方法提供智能自动关联逻辑，按优先级逐级匹配主体：

#### 算法步骤一：确定主体来源

```
1. 优先使用 lastUsedSubjectIds（最近使用的主体ID列表）
2. 若 lastUsedSubjectIds 为空，则向上追溯：
   - 单集关联：从 targetEpisodeIndex - 1 开始递减遍历，查找最近一个有主体的集数
   - 全局关联：直接使用全部主体
3. 若仍未找到，则使用全部主体作为备选
```

#### 算法步骤二：执行关联更新

```
单集关联模式（targetEpisodeIndex 有值）：
- 遍历所有主体
- 若主体ID在 sourceSubjectIds 中：确保 appeared_episodes 包含 targetEpisodeIndex
- 若主体ID不在 sourceSubjectIds 中：从 appeared_episodes 中移除 targetEpisodeIndex
- 更新 lastUsedSubjectIds = sourceSubjectIds

全局关联模式（targetEpisodeIndex 无值）：
- 遍历所有主体
- 若主体ID在 sourceSubjectIds 中：appeared_episodes = [全部剧集索引]
- 若主体ID不在 sourceSubjectIds 中：appeared_episodes = []
- 更新 lastUsedSubjectIds = sourceSubjectIds
```

### 3.2 手动关联回显规则

打开手动关联弹窗时，系统根据当前关联模式自动回显已选中的主体：

**单集回显逻辑**：
- 遍历所有主体，筛选 `appeared_episodes?.includes(props.episodeIndex)` 的主体
- 将这些主体的 ID 填充到 `selectedSubjectIds` 中，UI 展示为选中态

**全局回显逻辑**：
- 遍历所有主体，筛选 `appeared_episodes` 包含所有剧集索引的主体
- 即：主体出现在每一集中，才被全局回显为选中态
- 若某主体仅出现在部分集数中，全局回显时不被选中

### 3.3 主体类型识别规则

系统对主体类型进行统一标识与分类，关联弹窗按类型提供筛选能力：

| 类型标识 | 类型名称 | 图标 | 适用场景 |
|---------|---------|------|---------|
| `character` | 角色 | User（用户图标） | 人物、角色、演员等 |
| `scene` | 场景 | Location（定位图标） | 背景、场景、环境等 |
| `prop` | 道具 | Box（盒子图标） | 物品、道具、装饰等 |

## 四、重复关联数据处理规则

### 4.1 覆盖关联（全量更新）

用户执行手动关联并确认时，系统对目标剧集执行全量覆盖更新：

**覆盖逻辑**：
- 单集关联：将目标集数的 `appeared_episodes` 完全替换为用户当前选中的主体集合，原有该集关联记录被清空并按新选择重建
- 全局关联：将目标全剧的 `appeared_episodes` 完全替换，未选中的主体将从所有剧集的关联中移除

**示例场景**：
- 第1集原有关联主体：A、B、C（共3个）
- 用户手动关联弹窗中选中：A、D（共2个）
- 确认后第1集关联主体变为：A、D（B、C 被移除）

### 4.2 增量关联（自动关联默认行为）

自动关联逻辑执行增量关联，保留原有已关联的主体，仅追加新的关联：

**增量逻辑**：
- `autoAssociateSubjects` 方法使用 `lastUsedSubjectIds` 作为来源
- 将来源主体集合与目标集数进行合并，执行 `Set` 去重后更新
- 不会主动移除已有的关联关系

**示例场景**：
- 第1集原有关联主体：A、B（来自初始化或上次关联）
- 执行自动关联，来源主体为：B、C
- 自动关联后第1集关联主体变为：A、B、C（B 保留，C 新增）

### 4.3 跳过关联（导入场景）

在分镜脚本导入场景中，若目标剧集未完成主体设置（`assetsStatus !== 'success'`），系统执行跳过关联：

**跳过逻辑**：
- 将该剧集加入 `episodesSkippedNoAssets` 列表
- 跳过该剧集的主体自动关联
- 在导入结果提示中告知用户：「第 X 集未完成主体设置，已忽略关联」
- 该剧集的分镜脚本仍可正常导入，但主体需用户后续手动关联

## 五、关联异常校验与边界处理规则

### 5.1 空主体库校验

**触发条件**：用户尝试打开关联弹窗或执行自动关联时，系统检测到 `subjects.length === 0`

**处理逻辑**：
- 阻断关联操作，不打开弹窗或不执行自动关联
- 展示引导提示：「暂无可用主体，请先在主体设置中创建角色、场景或道具」
- 提供快捷跳转按钮：「前往主体设置」

### 5.2 空剧集校验

**触发条件**：用户尝试执行全局关联时，系统检测到 `episodes.length === 0`

**处理逻辑**：
- 阻断全局关联操作
- 展示提示：「暂无剧集数据，请先创建剧集」

### 5.3 单集越界校验

**触发条件**：用户传入的 `episodeIndex` 超出当前剧集范围（大于总集数或小于1）

**处理逻辑**：
- 自动关联时：跳过该越界索引，仅处理有效剧集
- 手动关联时：弹窗回显逻辑中过滤无效索引，避免出现 `undefined` 异常

### 5.4 关联状态一致性校验

**触发条件**：页面加载、数据恢复、跨页面切换时

**处理逻辑**：
- 通过 `loadFromLocalStorage` 恢复状态后，执行数据一致性检查
- 校验 `appeared_episodes` 中的索引值是否均在当前剧集范围内
- 超出范围的索引值自动清理，避免脏数据导致后续关联异常

### 5.5 并发操作保护

**触发条件**：用户在快速连续点击关联按钮或弹窗确认按钮

**处理逻辑**：
- 手动关联弹窗确认按钮设置 `loading` 状态，防止重复提交
- 关联操作执行期间禁用确认按钮，操作完成后恢复
- 自动关联逻辑执行期间，关联按钮置为不可点击状态

## 六、关联主体与业务流程的衔接规则

### 6.1 与分镜导入的衔接

分镜脚本批量导入流程中，关联主体作为可选后置步骤：

**衔接流程**：
1. 用户在导入方式选择弹窗中勾选/取消「导入后自动关联主体」选项（默认勾选）
2. 分镜内容完成解析、校验、落库后，若选项为勾选状态，自动触发 `autoAssociateSubjects`
3. 导入结果提示中明确告知：「已自动关联最新主体设置」或「主体关联已跳过」

**导入覆盖与关联的优先级**：
- 导入的覆盖/跳过策略优先于主体关联
- 被跳过的剧集（用户选择不覆盖）不进行主体关联
- 被覆盖的剧集在分镜数据清空重写后，执行新的主体关联

### 6.2 与分镜生成的衔接

分镜脚本生成（StoryboardView）流程中，关联主体直接影响生成内容的角色、场景一致性：

**衔接逻辑**：
- 分镜生成前，系统读取当前剧集的关联主体列表（`appeared_episodes` 包含当前集索引的主体）
- 将关联主体的 `prompt`、`image` 等字段作为生成上下文的约束条件
- 确保分镜画面中的角色形象、场景风格与已关联主体保持一致

### 6.3 与主体编辑的衔接

主体信息编辑后，已建立的关联关系保持不变：

**衔接逻辑**：
- 用户修改主体名称、形象、提示词等字段，不影响 `appeared_episodes` 关联数据
- 主体删除时，系统级联清理所有剧集 `appeared_episodes` 中该主体的关联记录
- 新增主体时，系统不自动关联，需用户手动或自动关联触发

## 七、UI 交互规范

### 7.1 关联主体弹窗规格

| 属性 | 规格 |
|------|------|
| 弹窗宽度 | 720px |
| 弹窗样式 | modern-dialog-v2，圆角 24px |
| 主体网格 | 3列网格，间距 16px |
| 主体卡片 | 方形缩略图 + 名称标签，圆角 16px |
| 搜索框 | 圆角 12px，前缀搜索图标，支持清空 |
| 分类筛选 | 单选按钮组：全部/角色/场景/道具 |
| 最大高度 | 400px，超出滚动 |

### 7.2 按钮状态与反馈

| 状态 | 样式 | 说明 |
|------|------|------|
| 默认 | 白底 + 靛蓝文字 + 圆角 | 未关联状态的按钮 |
| 悬停 | 上浮 + 阴影增强 | 鼠标悬停时的微动效 |
| 加载中 | loading 状态 + 禁用 | 关联操作执行期间 |
| 成功反馈 | ElMessage.success | 操作成功后的顶部提示 |
| 错误反馈 | ElMessage.error | 操作失败后的顶部提示 |

### 7.3 关联状态可视化

- 剧集卡片展示已关联主体的数量统计（`roleCount`、`sceneCount`、`propCount`）
- 分镜编辑页面侧边栏展示当前集关联主体列表，支持快速跳转编辑
- 主体库页面展示每个主体的关联集数（`appeared_episodes.length`），直观反映主体使用频率

## 八、数据持久化与恢复

### 8.1 LocalStorage 存储结构

```json
{
  "episodes": [...],
  "subjects": [
    {
      "id": "subject-001",
      "name": "男主角",
      "type": "character",
      "appeared_episodes": [1, 2, 3, 4, 5]
    }
  ],
  "subjectId": "subject-001",
  "lastUsedSubjectIds": ["subject-001", "subject-002"],
  "generationStatus": { ... }
}
```

### 8.2 恢复流程

1. 页面挂载时调用 `loadFromLocalStorage()`
2. 解析存储数据，恢复 `subjects` 及其 `appeared_episodes`
3. 恢复 `lastUsedSubjectIds` 用于下次自动关联
4. 数据绑定至响应式状态，UI 自动回显关联状态
